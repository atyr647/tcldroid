## Reading this list

- **Unchanged upstream code is reused**: all widgets, geometry managers, bindings, the canvas/text engines and ttk compile as-is. The platform layer implements the *Xlib-shaped API* Tk calls, not new widgets.
- **Several families are bookkeeping on Tk's own data**, not rendering: the window tree, properties/atoms, selection, event queue, focus. On Android these operate on in-process records (no X server), exactly as on macOS and Windows.
- **The genuinely platform-specific work** is: drawing and images, fonts/text, regions, input (keyboard/IME/touch), the window-manager policy, and menus. Rendering and text are the decisions ADR 0002 defers to a spike.
- Items marked unsupported by policy are expected to be stubs that raise a clear Tcl error.
